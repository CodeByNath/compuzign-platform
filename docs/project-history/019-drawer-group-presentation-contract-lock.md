# Drawer Group Presentation Contract Lock

## Date

2026-08-09

## Scope

This milestone touches only documentation: `docs/architecture/StationDrawerLifecycleContract-v1.md` (new §9–§12), `AGENTS.md` (one pointer paragraph), and stale-wording corrections in `docs/code-map/drawer-system.md`, `docs/code-map/tiers.md`, and `docs/code-map/tier-edition.md`. No source file was added, removed, or modified. The presentation patterns being locked here — the Tabs/Accordion group model, `ChildChipStrip`, `FocusedTaskShell`, the confirm-dialog convention, and the dual-split footer — already existed in source from the completed Tier Edition and drawer/footer refinement work; this milestone only codifies them into the platform's locked contract and corrects code maps that had fallen behind that source.

## Goal

The Tier occupant/Edition drawer introduced several new drawer-composition patterns that had no home in the locked [Station and Drawer Lifecycle Contract](../architecture/StationDrawerLifecycleContract-v1.md): a four-group Details/Options/Connections/Support content model with a Tabs/Accordion view toggle, a child chip-strip navigation primitive for a group's own child records, a generic focused-task shell for full-view detours (the Edition bin), a CSS-driven mechanism for suppressing drawer chrome while an editor or focused task is open, a confirm/prompt dialog convention, and a dual independent-split footer for records with a second, independently publishable child collection. The goal was to lock these into the platform's must-follow contract — the same way Service/Category/Tier occupant lifecycle was locked in §1–§8 — so any future Station or drawer that needs more than the fixed two-tab drawer follows one documented shape instead of a new bespoke implementation, and cannot be changed without going through this document first. A secondary goal was to correct code-map claims that had drifted from source during that work.

## What Changed

`StationDrawerLifecycleContract-v1.md` gained four new locked sections, verified against current source rather than against prior documentation: §9 (drawer group presentation — `drawerGroups.ts`, `DrawerGroupTabs.tsx`, `DrawerGroupAccordion.tsx`, `ChildChipStrip.tsx`, `useScrollHide.ts`, `FocusedTaskShell.tsx`), §10 (chrome suppression via a class toggle on a statically mounted tree, plus the optional `setHeaderHidden` bridge and its host-guaranteed reset), §11 (the confirm/prompt dialog convention — no shared modal component exists; `components/modal/index.ts` is a dead stub — and a recorded gap in the Edition bin's destructive-action guards), and §12 (the footer split-button grammar: the default single-split-plus-primary-Publish shape, and the additive dual independent-split shape `TierDrawerFooter.tsx` implements). The document's Scope line and Related Maps list were updated to match. `AGENTS.md`'s existing "Locked station/drawer lifecycle contract" paragraph gained one pointer to the new sections so a reader lands on them from the same entry point as the lifecycle rule.

Three code-map inaccuracies found while verifying source were corrected: `tiers.md` described `TierDrawerFooter.tsx` as a single-split-plus-primary-Publish footer, which stopped being true once the dual-split/`menuOnly` model shipped — it now describes the actual LEFT/RIGHT split shape and the four-group content model, and no longer claims a primary Publish button exists. `drawer-system.md`'s Shared Drawer Kit inventory omitted `FocusedTaskShell.tsx` and every `ui/` group-presentation primitive entirely; it now lists them. `tier-edition.md` said `useTierEditions.ts` owns "twelve endpoints" where its own enumeration, and `package-station/CLAUDE.md`'s independent count, both total eleven; corrected to eleven. Both edited code maps required several rounds of trimming to stay under the repository's 600-prose-word-per-map limit, resolved by preferring backtick-quoted identifiers (excluded from the word count) over spelled-out prose and by merging redundant bullets rather than dropping content.

## Final Architecture

§1–§8 of the contract remain the identity/persistence/lifecycle/pill/notification contract, unchanged. §9–§12 add a presentation-layer contract that sits above it: optional to adopt — most drawers still render through `EntityDrawer.tsx`'s fixed two-tab `DrawerTabs.tsx`, which remains the platform default — but mandatory in shape once a Station's drawer needs more than that fixed bar. Today the Tier occupant/Edition drawer is the only full adopter of the group/chip-strip/focused-task/dual-split pattern set; `TierEditionEditor.tsx` uses `DrawerGroupTabs` alone, and no other entity (Service, Category, Package Family, Tier Group/System) has adopted any of it. The primitives themselves (`drawer-kit/ui/*`, `FocusedTaskShell.tsx`, the `menuOnly`/`splitForward` footer capabilities) are drawer-kit-owned and carry no Tier-specific vocabulary, so a future adopter is expected to reuse them directly rather than re-implement an equivalent.

## Decisions and Invariants

Tabs/Accordion selection is per-drawer-instance, unpersisted view state — it must never be saved as a preference or entity default. `--cz-drawer-group-chrome-h` is the one contract between the active group renderer and nested sticky child navigation; a child strip must read it rather than hardcode an offset. A focused task (the Bin pattern) must be the sole visible identity for its concern — never rendered alongside a second nav row. Chrome suppression during an open editor or focused task must be a CSS class toggle over a statically mounted tree, never a remount swap that would wipe the open editor's local state; a host's optional `setHeaderHidden` capability must reset on every content-identity change independent of the content's own cleanup. There is no shared modal/prompt component and none should be assumed or introduced without new evidence of a second identical consumer — confirm overlays remain a per-entity `*DrawerDialogs.tsx` sharing only a CSS convention, and `useInlineConfirm` remains the separate, non-modal, per-row bin/travel primitive. The footer has exactly two locked shapes — default single-split-plus-primary-Publish, or the additive dual independent-split with `menuOnly` and Close beside the LEFT split — and no third shape is permitted. The Tier Edition bin's Move-to-Bin, Publish Edition, and in-bin permanent-delete actions currently fire with neither confirm mechanism, unlike the occupant bin's `useInlineConfirm`-armed delete; this is recorded as a known deviation to close, explicitly not as the pattern a new Station should copy.

## Validation

`npm run docs:check` passes (94 Markdown files, 34 Code Maps, 19 numbered history records) from a clean run after all edits, confirming no broken links/anchors and both trimmed code maps under the 600-word limit. Every behavioral claim in §9–§12 and in the corrected code-map text was verified by reading current source directly — `drawer-kit/ui/drawerGroups.ts`, `DrawerGroupTabs.tsx`, `DrawerGroupAccordion.tsx`, `useScrollHide.ts`, `ChildChipStrip.tsx`, `FocusedTaskShell.tsx`, `InlineEditorShell.tsx`, `EntityActionFooter.tsx`, `CanonicalEntityFooter.tsx`, `TierDrawerContent.tsx`, `TierDrawerFooter.tsx`, `tierLifecycleMenu.ts`, `TierEditionDeclarationSwitcher.tsx`, `TierEditionBinFocusedView.tsx`, `TierEditionBinList.tsx`, `useInlineConfirm.ts`, and `components/modal/index.ts` — rather than carried forward from prior documentation. This is a documentation-only change; `npx tsc --noEmit` and `npm run build` do not apply.

## Deferred Work

Closing the Edition bin's confirm-guard gap recorded in §11 (Move to Bin, Publish Edition, and in-bin permanent delete should gain the same guard the occupant bin already has) is left as follow-up implementation work, not part of this documentation milestone. No other Station has adopted the §9–§12 patterns yet; when one does, its Code Map should cite conformance the same way §8 already tracks lifecycle conformance.
